# Out of the beginner syllabus: what Phase 3 uses and why

Everything else (classes, vectors, files, exceptions, inheritance, virtual functions) is what Phase 2 already uses. These things go beyond it:

1. **The Win32 API** (`windows.h`, window classes, the message loop, controls such as list views, status bars, check boxes, radio buttons, list boxes, `uxtheme`). Round two builds the whole program as ONE window made in code (`GuiShell.cpp`, `Page*.cpp`, `Theme.cpp`). It is needed because a native Windows window can only be made through the operating system. No extra library, no web view, no HTML or script. Only the files that start with `Gui` or `Page`, `Theme.cpp`, `gui_main.cpp` and `res/` use it; the business code (`Workflow`, `Tables`, `Queries`, `Dashboard`, `OfferStore`, `RecipientUpdate`) has no window code and is tested without a window.
2. **CMake and Ninja** (`CMakeLists.txt`). Builds the Phase 2 sources, the backend, the eight test programs and the window program, runs all tests with `ctest`, builds the Release version and installs the dist folder (`cmake --install`). Two small CMake scripts (`tests/RunGuiTest.cmake`) run the test modes of the window program on a copy of the data.
3. **Resources and the manifest** (`res/gui.rc`, `res/app.manifest`, `res/app.ico`). A resource script compiled by `windres` puts the version information, the icon and the manifest into the exe. The manifest switches on the new look of the controls (Common Controls 6) and the screen scaling (DPI awareness).
4. **Static linking** (`-static -static-libgcc -static-libstdc++`). So `communitybridge_gui.exe` runs on a computer without MinGW.
5. **DPI scaling and fonts.** Every size is a "design pixel" multiplied by the screen scaling (`px()` in `GuiLayout.cpp`), fonts are made from the Windows message font in `Theme.cpp`.
6. **PowerShell development tools** (`tools/make_icon.ps1`, `tools/bmp2png.ps1`, the scratch scripts in `docs/ui2/scratch`). They use the System.Drawing library that comes with Windows to draw the icon and to turn screenshots into PNG files. They are not part of the program.
7. **Test modes of the program** (`--selftest`, `--selftest-flow`, `--screenshots <folder>`). Command-line words that make the program check its own window: layout measurements, window messages that act like clicks, and pictures of the window. The flow test changes files, so it refuses the real data folders.
8. **Astryx design guide** (`docs/DESIGN_GUIDE.md`). The colours, font sizes and spacing follow the Astryx design system (MIT licence), read only through its documentation commands; no Astryx code, package or file is part of the program.
